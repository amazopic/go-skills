Bounded Parallelism

Process N items with at most K workers concurrently.

sem := make(chan struct{}, K)
for _, item := range items {
    sem <- struct{}{}
    go func(it Item) {
        defer func(){ <-sem }()
        process(it)
    }(item)
}

Generator

Goroutine emits values on a channel, returned as <-chan T.

func gen(in []int) <-chan int {
    out := make(chan int)
    go func(){
        defer close(out)
        for _, v := range in { out <- v }
    }()
    return out
}

Functional Options

The idiomatic Go way to pass optional configuration to a constructor.

type Server struct {
    addr    string
    timeout time.Duration
}

type Option func(*Server)

func WithTimeout(d time.Duration) Option {
    return func(s *Server) { s.timeout = d }
}

func NewServer(addr string, opts ...Option) *Server {
    s := &Server{addr: addr, timeout: 30 * time.Second}
    for _, opt := range opts {
        opt(s)
    }
    return s
}

// usage
srv := NewServer(":8080", WithTimeout(5 * time.Second))

Circuit Breaker

Fail fast for an unreliable downstream so it has time to recover.

type Breaker struct {
    failures   int
    state      string // "closed" | "open" | "half-open"
    openedAt   time.Time
    threshold  int
    cooldown   time.Duration
    mu         sync.Mutex
}

func (b *Breaker) Call(fn func() error) error {
    b.mu.Lock()
    if b.state == "open" && time.Since(b.openedAt) > b.cooldown {
        b.state = "half-open"
    }
    if b.state == "open" {
        b.mu.Unlock()
        return errors.New("circuit open")
    }
    b.mu.Unlock()

    err := fn()
    b.mu.Lock(); defer b.mu.Unlock()
    if err != nil {
        b.failures++
        if b.failures >= b.threshold { b.state = "open"; b.openedAt = time.Now() }
        return err
    }
    b.failures = 0
    b.state = "closed"
    return nil
}

FAQ

Frequently asked.

Why build this when go-patterns already exists on GitHub?
go-skills consolidates two upstream archives (theory + runnable code), adds a service-architecture methodology, and packages everything as Claude Code-compatible skills with rich frontmatter — so your editor surfaces the right pattern automatically.
Are the patterns idiomatic Go or GoF translations?
Both. Concurrency, messaging, stability, profiling, idiom — these are Go-native. Creational/structural/behavioral are GoF translated to Go with idiomatic adjustments (e.g., functional options replacing Builder where it makes sense).
How were the patterns vetted?
Every one of the 52 entries was written by a senior Go consultant — idiomatic Go, opinionated guidance on when the GoF shape fits and when a Go-native alternative wins. All 52 example packages pass go test -race; no upstream bugs left behind.
Will the examples run on my machine?
Yes — one shared go.mod at examples/. Run cd examples && go test ./.... Go 1.22+.
When will the MCP server land?
A future iteration. The mcp/ folder holds a roadmap-only README in v1; the protocol surface is sketched there.
Why Linear's design system?
Linear's near-black + single-accent aesthetic matches the content — dense, technical, no decoration. Editorial New + Geist Mono carry the typography.
License?
MIT. Use, fork, redistribute freely.
Does this support the methodology in non-English?
README is translated to 23 languages. Pattern bodies and methodology chapters are English-only in v1; localization is on the roadmap.
